# Title
Writing Skill

## Overview
Create clear, purposeful writing that preserves the requested meaning and fits its audience and format.

## When to use this skill
- The user asks to draft, edit, rewrite, or structure written content.
- The task needs user-facing copy, internal guidance, documentation, or a communication artifact.

## When NOT to use this skill
- The primary request is code implementation, source-based research, or a faithful summary of supplied material.

## Steps
1. Identify the audience, objective, format, tone, and required facts.
2. Organize the content around the reader's main question or decision.
3. Draft with concrete wording and remove repetition or unsupported claims.
4. Check accuracy, readability, requested length, and formatting before delivery.

## Guidelines
- Preserve intent and factual meaning; do not invent names, commitments, metrics, or citations.
- Use direct language, useful headings, and examples only when they clarify the message.
- Match the requested voice without sacrificing accuracy or accessibility.
- Keep notes about assumptions separate from the deliverable.

## Input
A topic or source text, intended audience, goal, format, tone, and any length or content constraints.

## Output
Polished content in the requested format, with assumptions or unresolved details called out separately if necessary.

## Examples
Input: "Write a concise release note for the new export option."
Output: A brief, user-centered note describing the change without implementation detail.

## Edge cases
- If audience or tone is missing, use a neutral professional default.
- If required facts are missing, use explicit placeholders only when the user expects a draft template.

## Notes (optional)
Do not add explanatory copy to an interface when the user asked only for the interface itself.
